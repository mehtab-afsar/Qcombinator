## Stage B — THE CHAT: real conversation, streamed (fix #2)

The reply pattern *"Got it — noted: X, Y, Z… I still need…"* is a template echoing the whole
extracted state every turn. Replace it with an actual model-driven conversation.

- **One question at a time, in a human voice.** The model receives: what's known, what's missing
  (from the gap-ranker — keep that logic as the model's *input*), and the founder's last answer.
  It replies like a sharp colleague: acknowledge briefly if useful, then ask the single most valuable
  next thing. **Never dump the full context back.** "Noted: [everything]" is banned.
- **Stream it.** Turn on streaming for this endpoint (`text/event-stream` or the framework's streaming
  response). The reply should type in, not land as a dead block. This alone transforms the feel.
- **Ask per-parameter, Claude-style.** Each Q-Score dimension needs specific evidence — design the
  *prompting* so the model asks for it naturally, not robotically. (e.g. instead of "how many months
  to replicate your tech?" cold — "you mentioned 9 specialist agents on a proprietary framework;
  if a well-funded team started today, roughly how long before they'd catch up?") Warm, specific,
  one thing. Use the founder's own words back at them, sparingly, to show you're listening.
- **Model:** through the router, the everyday tier is fine (this is conversation, not heavy reasoning).

Tests / proof: show me a real transcript from a live run — I want to *read* it and judge the voice.
**Stop. Wait for "go".**

- **Design it** to the `UX_SPEC` standard: clean, per-dimension, sentence case, the founder's real
  numbers surfaced. Use real-world framing where it helps ("here's how an investor would read this").
- Where a dimension is thin, say so honestly and point to what would strengthen it — don't pad.

## Stage E — EXTRACTION: make it reliable and honest (fix #5)

The flaky extraction is the raw-regex fallback with no OCR.

- **Add an OCR path** for scanned/image PDFs and image uploads (the model can read images directly —
  use vision through the router, or a proper OCR step). A pitch deck that's mostly images must not
  fall into garbage.
- **Fail honestly, never silently.** If extraction genuinely can't read a file, tell the founder
  clearly ("couldn't read this deck — it looks scanned; try X, or answer a few questions instead")
  rather than proceeding on empty/garbage text and producing a confident-but-wrong snapshot.
- **Confirm what was extracted before it counts.** A quick "here's what I pulled — right?" beat, so a
  bad parse gets caught by the founder, not baked into the score.
- Keep the good parts (page cap, size handling); replace the crude `latin1` regex with a real
  fallback + OCR.
